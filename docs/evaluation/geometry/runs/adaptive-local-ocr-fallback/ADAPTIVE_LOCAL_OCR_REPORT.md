## 4. Local-only acceptance gate (designed from evidence, evaluated offline only)

Computed from the OCR output + image only (never from ground truth); any rule ⇒ fall back to Vision:

| rule | detects |
|---|---|
| `EMPTY_OR_SHORT_TEXT` | < 10 chars of body text (diagram-only / unreadable ⇒ Vision decides `MISSING_PROBLEM_TEXT` vs `IMAGE_NOT_READABLE`) |
| `UNRECOGNISED_SYMBOL` | a character outside letters/digits/allowed math symbols |
| `VIETNAMESE_ORTHOGRAPHY` | a lowercase token with no vowel (`tr`, `nm`, `phng`) or a stripped geometry word that is not itself a valid syllable (`hinh`, `diem`, `duong`…) |
| `RELATION_SYNTAX` | unbalanced brackets; point tuple not exactly 3 `;`-separated components (`:` is a misread); lowercase/digit object name `(a)`, `(8)`; empty equation side; misread-only glyphs (`V3`, `x°`, `II`, `SA 1 (`) |
| `VERTEX_INCONSISTENT` | primed vertex without its base; repeated letter in a solid notation; prism top ≠ base primed; one apex/base with two notations |
| `DIAGRAM_UNEXPLAINED` | label-sized OCR lines whose letters the text never names; diagram-reference cue (`như hình vẽ`) |
| `DOMAIN_NOT_GEOMETRY` | product `detect_domain` refuses the text (diacritic-free text is refused here, `ISSUE-ARCH-ROUTE-D-DIACRITIC-FREE-INPUT`) |
| `PASS_DISAGREEMENT` | Tesseract second pass (PSM 6, 1.5× grey) disagrees on any math token |
| `CROSS_ENGINE_DISAGREEMENT` (variant) | the second engine (RapidOCR) disagrees on any math token (numbers, vertex names, symbols) |
| thresholds | min line confidence ≥ `t_conf`, uncovered-ink ratio ≤ `t_uncovered` (figure ink / missed text), grid-searched |

Calibration: `calibrate()` maximises accepts subject to **0 unsafe accepts** (unsafe = accepted text ≠ ground truth
after lenient normalisation, or no problem text). Calibration set = all 22 items; **not held out**. The gate never
corrects a text — it only accepts or falls back.

Calibration findings (honest record):
- The first scoring run flagged correct Tesseract text because the stripped-word lexicon contained valid unaccented
  syllables (`qua`, `tam`, `trung`, `giao`, `xung`, `quanh`); the lexicon was cut to non-syllables and the same raw
  OCR outputs were re-scored (`ocr_outputs_reused_from_previous_child_run = true` in the receipt).
- **Single engine: no safe operating point exists.** Rule-only, Tesseract fast lets 9 texts through and 3 of them carry
  a wrong math fact (`(β) → (B)` in c06, `a√2 → aV2`, `a³ → a3`, `M₁ M₂ → Mạ M;` in s04 ×2). `(B)` is a valid plane
  name: no text-only rule can see it. The grid's only 0-unsafe point accepts 0 images.
- **Cross-engine (Tesseract fast text + RapidOCR math-token vote):** 0 unsafe in-sample; 3/22 accepted with PP-OCRv6
  small (`c03`, `c07`, `c10`), 5/22 with medium or v5-latin (adds `c02`, `c09`; `c09` has a sphere diagram whose
  Vision `diagram_observations` would be skipped ⇒ 1 missed-diagram observation; its text is exact).
  Tesseract best never passes its own second-pass check.

## 5. Vision provider calls — same 22 images, before vs after (mock provider; network calls 0)

Root cause of `class_09_diagram_only` spending 2 calls: `_process_normalized_visual_page` retried the full page
whenever the crop reading said `MISSING_PROBLEM_TEXT` / `missing_regions`, even when the crop already contained every
layout block of the page (diagram-only page: one figure block; crop = figure + margin). The full page adds only blank
margin, so the second call re-reads the same content.

Fix (`region_detector.py`, `unified_input.py`): `RegionDetectionResult.crop_holds_all_content` (default `False`) is
`True` only on the crop path when the page was **not** desk-trimmed and **every** block, noise included, lies inside the
crop. With it `True`, `missing_regions` / `MISSING_PROBLEM_TEXT` no longer retry; `IMAGE_NOT_READABLE` keeps its single
retry (different pixels). The first version ignored noise blocks and desk trimming and turned the existing 20-case
check `C19_CANCEL_IN_FLIGHT_AND_SAFE_FULL_IMAGE_FALLBACK` red (desk photo whose missing line is recovered only from the
untrimmed image) — tightened to the version above; C19 green again. "before" in the receipt is reproduced exactly by
forcing the flag to `False` (with it `False` the new predicate is the base predicate).

Measured counts (before 23 → after 22 calls on the 22 images; multi-image journey 3 → 2; second pass 0 calls /
22 cache hits in both modes; real network calls 0) are Table 6; local-only rate shipped = 0 % (no OCR).
 Table 7 gives the PREDICTED calls/rates if a cross-engine gate ran before

## 7. Why local OCR does not ship (verdict reasoning)

1. **Accuracy vs baseline cannot be shown.** Vision accuracy on these images is `NOT_MEASURED` (mock only).
2. **Single-engine Tesseract silently changes math facts** (3 of 9 rule-accepted texts); no calibrated single-engine
   gate keeps facts intact while accepting anything.
3. **The only safe in-sample variant needs two engines**: Tesseract (system package) + RapidOCR/onnxruntime/OpenCV —
   ~0.75 GB peak RSS and ~1.3 s CPU per image more (Table 3) to avoid ~14–23 % of Vision calls, calibrated on 22
   synthetic images, 0 held out, 0 real photos.
4. Packaging (not executed): `python:3.12-slim` is Debian trixie — `apt-get install tesseract-ocr tesseract-ocr-vie`
   (`tesseract-ocr 5.5.0-1+b1`, 2,279 kB installed plus `libtesseract5`, `libleptonica6`, pango/cairo, ICU…, total
   `NOT_MEASURED`; `tesseract-ocr-vie 1:4.1.0-2`, 534 kB installed — consistent with `tessdata_fast`, the variant that
   measured best; packages.debian.org read 2026-11-09), plus pip `pytesseract`/`tesserocr` and
   `rapidocr onnxruntime opencv-python-headless numpy shapely pyclipper` (Windows installed sizes: onnxruntime 48 MB,
   cv2 115 MB, numpy 55 MB, RapidOCR small models 31.7 MB; Linux sizes `NOT_MEASURED`). The apt part is a second
   manifest the repo does not have. Nothing added: the verdict is not VERIFIED.

Scope (RULES §3): building the two-engine stack would be **DEEP_HARDENING** — a large runtime surface for a secondary
capability, tuned on one small in-sample set. Smallest acceptable path: keep Vision; keep the benchmark and gate as a
diagnostic tool; revisit only with a labelled real-photo corpus and a measured Vision baseline.
