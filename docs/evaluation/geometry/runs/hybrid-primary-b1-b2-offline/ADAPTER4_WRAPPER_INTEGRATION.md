# Product Adapter /4 wrapper

`build_adapter4_response` promotes wrapper composition out of evaluation harnesses into the owning adapter. Output is `{schema_version: hybrid-route-d-simulation/4, envelope, route_d}` with adapter `/4` and canonical `typed-fact-next/2` identities. The exact route itself remains the existing single Source Gate/Planner/Engine path.

Before serving, the producer checks original-source hash, gated quote membership, current planner identity, source authority, kernel success, scene dependency/metric agreement, exact-memory point coordinates and quantities, complete source ask IDs, engine-derived answer dimensions and display text, unit coherence, section/provenance/closure consistency, non-proof observations/text, and validated non-truncated semantic envelope config. Emitted certificates are deep-copied to avoid comparing shared mutated authority.

Refusals use the existing classifier and learner wording. Their route_d has only identity, REFUSED status and code; no raw detail, calls, answers or old scene survives. The existing frontend accepts these wrappers, validates their scene bindings and clears active state after refusal.

Independent review found source relabel, answer/coordinate/planner binding, certificate aliasing and measurement taxonomy defects. Each was addressed before final candidate; INDEPENDENT_REVIEW records reproductions and regression evidence. No proof is upgraded from a single constructed configuration. Payload config.frames narration remains present under the pre-existing contract and is not rendered by Scene3D; existing F5 browser assertions still apply.
