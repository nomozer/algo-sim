## Status and gap vocabulary

Layer cells: **S = SUPPORTED** for the stated bounded operation; **P = PARTIAL** for the complete group; **R = REFUSED** at a concrete current boundary; **N = NOT_MEASURED** where acceptance has not been established. Upstream refusal does not demonstrate that an unexecuted downstream gate itself refuses. Scene3D capacity is representation, not source-grounded solving. `Overall` describes the complete canonical Hybrid configuration; legacy render-only demonstrations do not upgrade it.

Gap codes expand to the requested taxonomy: X=`EXTRACTION_GAP`; G=`SOURCE_GROUNDING_GAP`; C=`SCHEMA_CONTRACT_GAP`; F=`REGISTRY_FUNCTION_GAP`; P=`PLANNER_COMPOSITION_GAP`; E=`EXACT_ENGINE_GAP`; A=`ADAPTER_INTEGRATION_GAP`; V=`SCENE3D_PRESENTATION_GAP`; M=`EVALUATION_EVIDENCE_GAP`. Multiple codes identify distinct missing obligations, not a claim that every layer was executed.

Schema means V2 representation; Gate means source grounding; Registry means available functions; Contracts means internal planning/effect contracts. All rows have X/M for full-family extraction and independent acceptance: authored TypedFacts, old model runs and plausible pictures cannot establish those properties.
