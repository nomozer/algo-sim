## Confirmed defects and corrections

1. **Refusal classification and duplicate codes.** The original browser audit inserted the raw code twice and supplied `failure_category=postcondition_violated` to a notice whose fallback title was unsupported-family text. Our before browser reproduction independently shows the misleading unsupported title and raw code. The product notice now distinguishes known unsupported, inconsistent, insufficient, ambiguous and internal-verification categories. For the sphere case the main text says the requested intersection cannot be constructed, preserving the backend explanation that the plane is farther from the center than the radius. The shared code also occurs for cylinders/cones: their authoritative explanations are retained. Exact code tokens and raw reason stay in collapsed diagnostic details. Existing UNKNOWN/SOURCE attribution and backend refusal decisions remain unchanged.
2. **Section depth.** Circular/elliptical fills used `AlwaysDepth`; polygonal section/auxiliary fills bypassed `depthTest`. A real fill behind an opaque wall painted through it. Default fills now use the ordinary depth comparison. `depthWrite=false`, render ordering, tiny polygon offset, opaque curved-solid depth prepass, and visible/hidden boundary passes remain. Explicit **Nhìn xuyên khối** reveals interior fills and displays a visible mode explanation. It resets on scene changes. Cone axial-section fill construction remains present and is inspectable in explicit x-ray mode.
3. **Analysis identifiers.** Ratio and residual-volume labels used raw solid keys. The analysis model now resolves verified `route_d.solids[].scene_object_id` mappings into scene display names; unknown names use an honest generic fallback. Unsafe identifiers in labels/notation/formulas/basis labels are withheld. Exact result values are unchanged. Numeric powers render as superscripts; π, radicals, slash fractions and dimensionless ratios retain exact backend strings.
4. **First-load framing.** Cardinal radial sample points formed an inscribed cross, so diagonal camera projection could underestimate curved models before mesh construction. Browser reset differed from first fit; the sphere reached/clipped the canvas edge. Conservative enclosing corners in the existing radial basis fix this without changing payload coordinates, geometric authority or timeline semantics. Cone expansion remains at its base, plus apex.
5. **Entry guidance.** The actual workspace starts at the first construction state, not the complete model. Some scenes therefore initially contain only points (sphere: one point). Guidance now names the existing Play/Next controls and offers **Xem mô hình đầy đủ**. That action moves to the last genuine construction anchor. Simulation remains default; final numeric answers remain hidden until explicit Mathematical Analysis.

## Non-defects and mathematical units

The oblique-cylinder input explicitly says `R=2a`, `h=6a` and declares `length_unit="a"` in the typed input; the verified route summary also carries `length_unit="a"`. Thus `4π√2a²` and `24πa³` are genuine symbolic results, not invented units. Scene values `R=2`, `h=6` are normalized coefficients. The analysis panel now explains that length unit and the meaning of those coefficients. Unitless cylinder values stay unitless. No units were silently removed, and no values were recalculated in the frontend. Given quantities, derived quantities, requested results and certificates retain separate groups.

The hidden-line depth prepass and two-pass curved boundaries are intentional, not defects. Existing disabled-depth materials used for invisible pick proxies, annotation witnesses and CPU-classified canonical edges were audited and retained; no global depth-test switch was introduced.
